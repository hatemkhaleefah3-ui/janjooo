PROJECT

Jang PPTX Template Engine

PURPOSE

This is a reusable TypeScript engine that generates native, editable PowerPoint lectures from strict structured JSON and user-imported images.

It must not convert HTML to PowerPoint.

The existing project already contains:

- TypeScript lecture types
- JSON Schema
- Ajv validation
- PptxGenJS rendering
- React demonstration interface
- cover, overview, section, content, image, table, diagram, and ending renderers
- pagination helpers
- tests
- a working sample PPTX generator

Your task is to finish, repair, test, document, and package the existing work.

C. FIX PAGINATION

The current pagination only moves whole blocks and can omit or clip content.

Implement deterministic pagination that never silently drops content.

Required behavior:

- Long paragraphs split at sentence boundaries.
- If a sentence itself is too long, split safely by words.
- Bullet lists split between items.
- Numbered lists split between items while preserving numbering.
- Tables split between rows.
- Table headers repeat on continuation slides.
- Diagrams split between logical rows or groups.
- Images are never split.
- Source order is preserved.
- Continuation slides retain the section header.
- Continuation slides do not repeat the original slide title.
- Relevant subtitles may be retained when needed.
- No renderer loop may use `break` in a way that silently discards remaining blocks.
- No content may be summarized merely to make it fit.

Add explicit pagination result types so the renderer knows which fragment is a continuation.

D. FIX INLINE TABLE CONTINUATION

The current inline table renderer can display “continued” without actually creating a continuation slide.

Correct this behavior.

Requirements:

- A small table may share a slide only when all rows fit readably.
- If all rows do not fit, either:
  1. move the whole table to dedicated table slides, or
  2. render real continuation slides.
- Never omit table rows.
- Repeat headers on each continuation slide.
- Use a safe minimum font size.
- Never clip cell text.
- Continue until every row is rendered.

E. FIX IMAGE HANDLING

The schema supports `contain` and `cover`, but the renderer currently always uses contain.

Implement both correctly.

Requirements:

- `fit: "contain"` preserves the whole image.
- `fit: "cover"` fills the target area and crops only when explicitly requested.
- Determine actual image dimensions from the imported data URL when possible.
- Do not rely only on `preferredAspect`.
- `preferredAspect` is a layout hint, not a replacement for intrinsic dimensions.
- `automatic` must never stretch an image.
- Preserve aspect ratio.
- Support PNG, JPEG, and other formats supported by PptxGenJS.
- If decoding fails, display a labeled placeholder and add a warning.
- Never crash the complete presentation because one image is invalid.
- Include tests for contain, cover, automatic aspect, missing image, and invalid image data.
